# Viya 操作流程

本文说明从首次登录到代理上线、修改和故障恢复的完整操作路径。界面按“先准备依赖，再创建规则；每次规则保存后立即校验并应用”的顺序组织。

侧边栏按 Lucky 的模块布局组织，每个入口对应独立功能页：运行概览、Web 服务、端口转发、动态域名、SSL 证书、DNS 凭据、IP 封禁、访问日志、配置历史。概览展示引擎状态和服务数量；其他页面只展示对应功能。顶部提供当前功能的新增入口和刷新按钮，侧边栏高亮当前页面。地址中的功能路径可直接访问，刷新和浏览器前进/后退会保留对应页面。旧版 `#dns-ddns` 地址兼容跳转到 DNS 凭据页。

## 1. 首次进入

1. 通过 `http://服务器地址:8181` 打开 Viya。
2. 首次运行创建管理员账户；后续使用该账户登录。
3. 登录后确认左侧状态显示“引擎已连接”。“运行概览”展示代理数量、Caddy 状态、最近配置版本和各服务入口；详细应用记录在“配置历史”页面查看。

## 2. 创建一个基础代理站点

1. 在“Web 服务”列表中按主域名查看代理站点。已有主域名时，点该分组的“添加子域名”，输入子域名前缀（例如主域名为 `viya.santi.fun`，前缀填 `api`，完整域名会预览为 `api.viya.santi.fun`）；主域名下的其他代理站点会显示在同一组。也可以选择“填写完整域名”，直接输入 `api.example.com` 等完整域名。再填写 Debian 主机能够访问的上游 URL，例如 `http://192.168.1.20:8080`。上游必须使用 HTTP(S)，端口可省略：HTTP 默认 80、HTTPS 默认 443。
2. 可选填访问路径，例如 `/api`，此时只转发 `/api` 和 `/api/*`；留空表示此域名的全部路径。站点图标提供十种颜色，默认海蓝色。Web 服务使用 HTTP / HTTPS 监听选项卡，默认端口为 80 / 443。点击选项卡会检测服务器本地端口；不可用时显示红色提示。可修改端口或添加监听，同协议监听共享域名规则。所有 HTTP 入口将 HTTPS 站点跳转到第一个 HTTPS 监听。公网防火墙放行与 ACME 验证端口需另外配置。
3. 可先点“测试上游连通性”。这是 TCP 端口探测，能确认网络端口可达，但不代表上游 HTTP 应用本身健康。
4. 选择 TLS：
   - **自动 HTTPS**：常规公网域名；确保 DNS 指向本机且公网验证端口可达。
   - **HTTP-01**：显式选择 HTTP 验证；需要公网 80 端口，不能用于泛域名。
   - **DNS-01**：需要先保存 DNS 提供商凭据，可签发泛域名证书。
   - **内部 CA**：适合内网；客户端需要信任 Caddy 内部 CA。
   - **自定义证书**：先上传 PEM 证书链和匹配私钥，系统校验证书/私钥、SAN 和有效期。
   - **仅 HTTP**：不申请证书。
5. 开启站点即可让 Caddy 接收请求；Basic Auth 在基础表单的“访问安全”区域设置。
6. 提交后，服务端验证域名、路径、端口、上游、证书/凭据和安全选项，写入数据库，再生成 Caddy JSON、运行 Caddy 校验，最后通过 Admin API 热加载。成功后站点列表和配置历史刷新。

站点行的“克隆”会复制上游、TLS、路径、图标和访问控制设置，并生成一个新的子域名；Basic Auth 密码不会被读取或复制，克隆时需重新输入。删除 Web 服务会先在 Viya 内显示确认框，确认后才删除并应用新配置。页面“刷新”会重新读取站点、证书、日志、端口转发、DDNS、封禁及运行状态；页面会显示最近一次成功刷新的时间，失败时显示错误。

## 3. DNS 凭据和证书等前置依赖

### 在 SSL 证书页申请

点击“申请证书”，填写名称、单个域名和验证方式。HTTP-01 使用 Let’s Encrypt，需要域名指向本机并让公网 80 端口可达；DNS-01 选择已保存的 DNS 凭据，可申请泛域名，不要求开放验证端口；内部 CA 面向内网，客户端需要手动信任根证书。邮箱可选。

申请记录可独立于站点保存，Caddy 通过证书自动管理模块在后台签发并续期。提交成功不等于签发完成；列表每 5 秒检查本机证书文件，显示等待签发、已签发或已到期以及签发者、到期时间。公网验证失败时 Caddy 按退避策略重试；请检查 DNS 权限、解析和验证端口。不得把内部 CA 的成功测试等同于公网 ACME 已通过。

相同域名的站点选择“自动 HTTPS”即可使用托管配置；如果站点已经使用另一种显式 TLS 模式，需要先改为自动 HTTPS。泛域名在已有 DNS-01 托管申请后也可选择自动 HTTPS。正在被自动 HTTPS 站点引用的托管配置不能停止；停止托管不删除 Caddy 缓存中的证书文件。DNS 凭据被托管申请引用时也不能删除，替换后会重新应用配置。

- DNS-01 站点需要先选择 DNS 服务商凭据。可以从站点表单中打开“添加 DNS 凭据”，保存后返回时站点表单仍保留；密钥在本地加密保存，列表不会回显。
- 替换已被 DNS-01 站点使用的凭据后，系统会重新应用 Caddy 配置，确保新凭据进入活动配置。
- 自定义 TLS 站点需要已上传的证书；可以从站点表单打开证书上传，完成后再回到原站点表单选择。
- 泛域名不能使用自动 HTTPS 或 HTTP-01；选择 DNS-01、内部 CA 或覆盖该名称的自定义证书。

## 4. 高级代理选项

### 站点访问日志与流量统计

在“Web 服务”页，只有将鼠标悬停在站点名称旁的日志图标上才会显示该站点最近 5 条访问日志；将鼠标移入预览卡片时卡片会保持打开。点击日志图标或卡片中的链接可展开最近 50 条记录。窄屏可点击日志图标查看。日志包含时间、来源 IP、方法、路径、HTTP 状态、上行/下行字节数和耗时；请求头、响应头和查询参数不写入站点日志表。展开窗口每 5 秒刷新，后台采集间隔为 2 秒。

页面汇总和站点行展示最近 24 小时（按整点小时汇总）的请求数、上行、下行和 4xx/5xx 请求数；站点行另有小时流量趋势及累计请求/流量。统计依据 Caddy JSON 中的 `bytes_read` 和 `size`，分别表示客户端请求体与响应体字节数，不包含 HTTP 头、TLS 和网络协议开销，也不统计 Layer4 流量。

统计首次接入时读取本机现存 `access.log` 及 Caddy 原生轮转的 `.log` / `.log.gz` 文件；已删除日志无法补算。小时汇总与读取位置持久化在 SQLite 中，服务重启和正常日志轮转不会重复计数，数据库备份会包含统计数据。站点日志每站保留最近 100 条供界面查询。累计值从首次可用日志接入开始计算。

站点表单的“高级设置”包含上游请求头、IP 白名单/黑名单和限速。每行一个 IP 或 CIDR；限速设为 0 表示关闭。Basic Auth 属于常用安全项，因此仍放在基础表单中。

编辑现有站点时，留空 Basic Auth 新密码会保留原密码；新建开启认证时必须设置至少 8 位密码。提交修改仍走相同的数据库保存、配置校验、热加载流程。

## 5. DNS 与 DDNS

1. 先添加受支持服务商的 DNS API 凭据。
2. 创建 DDNS 任务，选择凭据、DNS Zone、相对记录名（`@` 代表根记录）、A/AAAA、TTL 和 5 分钟以上的检查间隔。
3. 保存后任务由后台按间隔探测公网 IPv4/IPv6 并更新 DNS；可用“立即检查”触发一次运行，列表显示最近 IP 和错误。
4. 系统在发现同名同类型记录存在多个地址时拒绝覆盖，避免误删 RRset 中其他地址。

## 6. TCP / UDP（Layer4）转发

配置监听 IP、监听端口、上游 `host:port`、协议和启用状态。监听端口由 Caddy 直接绑定 Debian 主机，因此应检查防火墙，并避开 Viya 管理端口及 HTTP/HTTPS 端口。保存后同样热加载；端口冲突或 Caddy 不接受配置时，到配置历史查看原因。

## 7. 修改、删除和配置恢复

### 编辑 IP 封禁

“IP 封禁”页可手动新增或编辑规则：选择站点，填写 IPv4、IPv6 或 CIDR 网段、原因和未来一年内的到期时间。保存后立即让 Caddy 重新应用配置；数据库保存成功而应用失败时，可重试应用。编辑自动规则后会转为手动规则，自动防护不会覆盖手动 IP/网段的到期时间。后台每 2 秒检查过期规则，删除后重载配置，重载失败会继续重试。到期或解除后刷新列表可查看最新结果。

- 编辑站点、Layer4 或 DNS 凭据后立即应用 Caddy 配置。DNS 凭据本身只在被代理站点引用时触发 Caddy 重载。
- 删除操作会先删除数据库记录，再尝试应用新配置。若 Caddy 应用失败，界面会保留失败提示并提供“重新应用到 Caddy”；不要因为 502 就重复创建同一规则。
- 站点或 Layer4 保存返回 502 时，代表数据库记录已保存但 Caddy 尚未接受当前配置。界面会重新读取列表并识别已保存对象：先点“重新应用到 Caddy”；若需要修正，使用识别出的现有记录编辑，避免重复新增。
- 配置历史按时间记录 Caddy 配置应用成功/失败和诊断信息。先处理最新失败的原因，再重试当前配置。
- 数据库和密钥备份/恢复命令见项目 README 的 Linux 部署与备份章节。恢复密钥必须与加密凭据数据库匹配。

## 8. 故障排查顺序

1. “引擎未连接”：刷新状态并查看服务日志，确认 Caddy Admin API 就绪。
2. 上游不可达：在 Viya 上游测试中确认 TCP 端口，再检查 Debian 到目标主机的路由、防火墙和服务监听地址。
3. HTTPS 申请失败：确认域名解析、80/443 可达性、TLS 模式、DNS 凭据权限和泛域名限制。
4. 保存后返回 502：先看配置历史，确认记录已保存，修复原因后使用重试按钮，不要重复新增。
5. 请求异常：查访问日志；安全事件会隐藏敏感请求头和查询参数。误封 IP 可在“临时 IP 封禁”中解除。

## 9. 参考 Lucky 的设计取舍

Lucky 的 Web 服务流程先确定监听/TLS 条件，再添加域名到上游的规则，并区分简单模式和高级配置；其文档也明确说明 DNS-01、泛域名和上游配置的依赖关系。Viya 借鉴这个“常用必填项优先、复杂选项后置、前置依赖就地创建”的操作顺序。

Viya 的代理数据模型是 Caddy 的共享 HTTP/HTTPS 监听器下，每个代理站点对应一个域名主机；因此这里没有照搬 Lucky 的“每个 Web 服务独立监听端口，再在服务内添加子规则”结构，而是把监听器作为全局运行配置，把域名、上游和站点级策略放在代理站点。参考： [Lucky Web 服务文档](https://lucky666.cn/docs/modules/web/) · [Lucky GitHub](https://github.com/gdy666/lucky)。



## 监听和 DDNS 源码调整

- Web 监听配置保存在面板设置中，保存前检测端口冲突，生成独立的 HTTP / HTTPS 监听；新增监听沿用相同协议的站点规则。
- DDNS 列表提供自动更新复选框。关闭后暂停定时调度，仍可手动更新；正在执行的更新会完成后再暂停调度。
- DDNS 支持本地备注，默认 `viya`；列表每秒刷新更新记录，手动更新完成后立即显示服务器记录的时间，按钮提供旋转动画和结果反馈。
- Web 服务、端口监听、TCP/UDP、DDNS、DNS 凭据、证书和 IP 封禁使用统一的面板内确认弹窗；点击遮罩不会取消或执行删除。



## 面板设置

左下角“面板设置”按钮或 `Ctrl / ⌘ + ,` 打开右侧设置抽屉。外侧点击不会关闭；使用关闭按钮、完成按钮或 Esc 关闭。抽屉支持键盘焦点限制，窄屏下占满宽度。

- 外观与显示：主题、紧凑布局、流量趋势图、默认进入页面、恢复浏览器默认偏好。
- 刷新与日志：页面自动刷新开关、5/15/30/60 秒刷新间隔、后台暂停刷新、悬浮日志 3/5/10 条。关闭页面轮询不会停止服务器 DDNS 定时任务。返回前台时立即更新状态。
- 面板访问：复制访问地址、修改面板端口。提交前需确认已了解访问地址与反代上游的调整；域名反代访问不会自动跳转至域名加端口。
- 账户与会话：修改密码、查看有效会话数量、退出其他登录会话。关闭抽屉时清空密码输入。

浏览器偏好即时保存到本地；端口和密码需要单独提交。会话管理仅作用于当前管理员账户，并保留当前会话。

## 列表与页面说明

页面顶部统一提供标题、说明、更新时间、刷新和主要新增入口。点击“如何使用”可展开当前功能的操作步骤。Web 服务先选择监听，再搜索或筛选站点；其他列表可按名称、地址、域名等关键词查找。DDNS 和端口转发也支持状态筛选。列表显示匹配数量，无结果时可直接清除筛选。

Web 的流量摘要统计所有站点，搜索不会改变摘要口径；单个站点仍显示自己的流量。DDNS 列表的“上次执行”包含成功和失败尝试，失败原因另行显示。

编辑和新建弹窗支持键盘焦点循环，点击外侧保持打开；关闭后回到原操作位置。站点日志仍只在悬浮日志图标时预览。

## 本轮监听与证书更新

Web 站点按监听独立保存。新增监听默认空白，也可从已有监听复制全部站点规则；复制后互不影响。监听位于站点列表内，列表标题提供“添加站点”，分组内提供“添加子域名”。Web 标题旁的搜索图标可展开输入框；SSL 和 DNS 凭据页取消搜索。

Web 行内显示证书配置匹配结果；未匹配托管泛域名的自动证书同步出现在 SSL 的“站点自动证书”区域。运行概览加入真实服务监控和展示定制。账户设置支持修改用户名。配置历史顶部提供完整配置的加密导出及导入，历史最多展示 10 条。

完整方案、恢复范围和验证结果见 [本轮十项方案](next-iteration-plan.zh-CN.md)。
