# 文件与共享：权限范围

Viya 不再提供「服务器文件管理器」。文件相关的入口现在只有两个，权限模型完全不同，先分清它们。

| | 文件与共享工作台 | 站点文件管理抽屉 |
| --- | --- | --- |
| 入口 | 左侧「文件与共享」页（默认隐藏，需在面板设置里打开） | 工作台卡片上的「管理文件」 |
| 接口 | `GET /api/v1/file-shares`（只读清单） | `/api/v1/proxy-hosts/{id}/files/*` |
| 作用 | 查看所有静态站点与共享目录的配置、认证与读写状态 | 上传、编辑、下载、新建、删除站点文件 |
| 可写范围 | 无写操作 | 仅限面板托管目录 `/var/lib/viya/sites/<域名>` |

工作台的清单**只返回展示所需字段**（域名、类型、目录路径、启用状态、认证是否开启、认证账号、读写开关、目录浏览、访问地址），**不返回密码或密码哈希**。

## 两个权限边界

### 1. 应用层：共享目录 `root_path`

静态站点与文件服务站点共用一个 `root_path`（留空时自动落到 `/var/lib/viya/sites/<域名>`）。它只校验「绝对路径 + 不含 `..`」，**允许指向任意目录，包括 `/`**——所以填错目录会直接扩大对外可见范围。请只指向专用数据目录，例如 `/srv/share`。

站点文件管理抽屉则相反：写入必须落在托管目录内，`root_path` 指向外部路径时上传会返回 400「该站点目录由面板外部管理」，不受下面 systemd 权限影响。

### 2. 系统层：最终硬边界

面板与 Caddy 都以 `User=viya` 运行，并受 systemd 三层限制。任何一层都会挡住访问：

| 限制 | 默认值 | 影响 |
| --- | --- | --- |
| 运行用户 | `User=viya` | 非该用户拥有的 `700` 目录全部拒绝 |
| `ProtectHome=true` | 开启 | `/home`、`/root` 被空 tmpfs 遮蔽，列目录为空 |
| `ProtectSystem=strict` | 开启 | 整个文件系统只读挂载，只有 `ReadWritePaths` 例外 |

因此即使把 `root_path` 设成 `/`，实际能读的也只是 `viya` 用户有权限读的部分（`/etc/shadow`、证书私钥读不到），`/home`、`/root` 为空，写入基本失败。**是操作系统拦住了全盘访问，不是程序代码**。

## 认证与读写（最关键）

- **Basic Auth 是可选的，不是默认开启**：只有设置了账号和密码，`config_compile.go` 才会插入 `authentication` handler。未开启时，任何知道地址的人都能访问该共享。
- **`webdav_write` 是独立开关**：关闭时 `PUT/DELETE/MKCOL/...` 返回 405 并带 `Allow` 头；开启后客户端可上传、修改、删除。
- 两者叠加时风险最高：**允许写入 + 无认证** 等于把目录开放给所有人改写。工作台卡片会用警告横幅直接标出这种配置。
- 即使开启写入，写入范围仍被 `ReadWritePaths` 限制（默认 `/var/lib/viya /opt/viya/bin`）。要写外部目录，需按下面步骤授权，**不要给 `/`**。

## 需要共享外部目录时

1. 在站点表单里把共享目录填成已存在的绝对路径（如 `/srv/share`）。
2. 只需读：`setfacl -R -m u:viya:rX /srv/share`，敏感子目录单独 `---` 拒绝。
3. 需要 WebDAV 写入：在 systemd drop-in 里追加该目录到 `ReadWritePaths`，然后 `daemon-reload && restart viya`。
4. 始终开启 Basic Auth，并优先使用 HTTPS 监听（Basic Auth 在 HTTP 上是明文传输）。

```ini
# /etc/systemd/system/viya.service.d/60-share-write.conf
[Service]
ReadWritePaths=/srv/share
```

## 管理整台服务器的文件

面板不再承担这个职责。共享目录之外的文件请用：

- **SFTP / WinSCP / VS Code Remote**：通过 SSH 管理，权限与审计由系统控制；
- **WebDAV 客户端**：只挂载已发布的共享目录；
- **独立容器**（确需网页文件管理器时），把可访问范围限制在显式挂载内，避免扩大面板权限：

```bash
docker run -d --name files -v /srv/data:/srv -p 8182:80 filebrowser/filebrowser
```

## 路径与错误码

路径侧仍保留三道防线：拒绝 `..`、拒绝符号链接、用 `os.OpenRoot` 把站点文件操作限制在根内。因此扩大共享目录的可见范围，不会同时扩大可越界范围。

| 情况 | 状态码 |
| --- | --- |
| 外部目录发起站点文件上传 | 400 |
| 文件系统 `EACCES` / `EROFS` | 403 |
| 路径不存在 `ENOENT` | 404 |
| 路径含 `..` 或指向根外 | 400 |
