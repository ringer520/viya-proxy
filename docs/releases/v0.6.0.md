# Viya v0.6.0

这一版把「文件」这件事收敛了：删掉默认隐藏、只读、被 systemd 三层限制捆住的服务器文件管理器，换成「文件与共享」工作台。数据库结构不变，可直接升级。

## 移除：服务器文件服务

v0.4.0 加入的左侧「文件服务」页是一个通用文件管理器，但默认隐藏、`VIYA_FILES_READONLY=1` 默认只读，又受 `User=viya` / `ProtectHome` / `ProtectSystem=strict` 三层限制——实际只能看 `/etc`、`/var/log`，`/home` 为空、写操作全禁。能力与定位错位，且与站点文件管理重复造轮子（`serverFileEntry` 直接别名 `siteFileEntry`）。

本次删除：

- 后端 `cmd/viya/server_files.go`（629 行）、`routes.go` 里 10 条 `/api/v1/files/*` 路由；
- `main.go` 的 `filesRoot` / `filesReadOnly` 字段与 `VIYA_FILES_ROOT` / `VIYA_FILES_READONLY` 两个环境变量；
- 前端 `FileManager.vue`（583 行）与 `file-manager.css`；
- systemd unit、README 与架构说明里关于该页的描述。

`WebDAVSettingsModal.vue` 保留，弹窗样式拆成独立的 `webdav-modal.css`，入口移到新工作台。站点文件管理（`SiteFilesDrawer.vue` 与 `/api/v1/proxy-hosts/{id}/files/*`）不受影响。

## 新增：文件与共享工作台

- 入口仍在左侧「网络服务」组，**默认隐藏，需在面板设置里打开「显示文件与共享」**（沿用 `viya-show-file-services` 偏好键，升级后原有开关状态保留）；关闭时若正停留在该页会自动跳回概览。内部路由 id 保持 `#file-services`，书签与「默认进入页面」设置不失效。
- 新增只读接口 `GET /api/v1/file-shares`（`cmd/viya/file_shares.go`），聚合 `static` / `files` 两类站点，返回目录路径、启用状态、WebDAV 读写开关、目录浏览、认证是否开启、认证账号，以及按监听协议与端口拼好的访问地址。**响应不含密码或密码哈希**，由 Go 测试断言。
- 卡片直接展示权限状态：`需认证` / `匿名可访问`、`只读` / `可读可写`、`目录浏览`、`已停用`；对「未开启认证」「允许写入但未认证」显示警告横幅，把之前只能靠读文档才知道的风险摆到台面上。
- 一键「管理文件」复用现成的 `SiteFilesDrawer.vue`；WebDAV 地址与 Windows / macOS / Linux / rclone 挂载命令可一键复制；右上角「WebDAV 设置」保存后自动刷新清单。
- 页面底部给出 SFTP / WinSCP / VS Code Remote、WebDAV 与独立 `filebrowser` 容器的引导，明确「共享目录之外的文件由系统工具管理」。

## 文档

- `docs/文件服务权限.md` 改写为《文件与共享：权限范围》，保留文件名以免历史版本说明里的链接失效，内容改为两个新入口的边界、`root_path` 与 systemd 的相互作用、Basic Auth / `webdav_write` 双开关，以及外部共享目录的授权步骤。
- `README.md` / `README.en.md` 的安全提示改为「共享目录务必开启访问认证」，功能表更新。
- `docs/项目说明.md` 同步导航划分、页面职责与文件树。

## 升级说明

- 无数据库迁移、无新增依赖、无 Caddy 插件变更。
- `VIYA_FILES_ROOT` / `VIYA_FILES_READONLY` 若曾手工设置，升级后会被忽略，可直接从 unit / drop-in 里删掉。
- 若曾在面板设置里打开过旧「显示文件服务」开关，升级后该开关继续控制「文件与共享」页。
- 历史 release notes（v0.4.0 / v0.5.0）保留原描述，作为版本演进记录。
