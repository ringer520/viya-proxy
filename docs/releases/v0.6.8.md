# Viya v0.6.8

这一版把流量统计从「留存访问明细」改成**只保留聚合统计**，并修正了概览流量分析的几处显示口径。

## 只保留统计，不保存逐条请求

`site_access_events` 是每站点保留 100 条访问事件的明细表。它带来两个问题：数据库里长期躺着一份带 URI、客户端 IP、User-Agent 的请求副本；同时它只有 100 条，导致概览显示「Web 错误率 37%」时，点进异常定位却只能看到 133 条记录，两个数字永远对不上。

v0.6.8 起：

- **采集不再写逐条事件**，改为按「站点 × 小时 × 状态码」累加到新表 `site_error_hours`。表里只有计数，没有请求行、IP 和 User-Agent。
- **`site_access_events` 表被删除**（迁移 8）。历史明细在升级时一并清除，本来就只保留每站点 100 条，不承担历史追溯职责。
- **异常定位**改为读聚合表，展示「站点 / 状态码 / 次数 / 占该周期请求比例」，90 天窗口也能精确对上错误率；代价是不再有逐条明细。
- **站点详情的「最近访问」**改为直接读 `access.log` 文件并按域名过滤，与「访问日志」页同源。功能保留，但不再落库。
- **保留策略**只剩「流量统计保留天数」，`access_events` 设置项移除。旧配置里多出的字段会被忽略。

升级后数据库会明显变小（明细表与索引被删除，`VACUUM` 或下次自动整理后回收空间）。

## 概览流量分析的显示修正

实测一台机器 15 天的数据：11-06 单日通过 WebDAV 拉了 24 个无人机视频，下行 3.19 GB，占 90 天总下行 4.00 GB 的 80%。把它当纵轴上限，其余 14 天全部压在 2.3% 高度以下，趋势图必然是一条平线加一根尖峰。

- **纵轴按 p90 封顶**，超出的点按上限绘制，并在右上角标注真实峰值（如「峰值 3.19 GB · 11/6」）。日常流量恢复可读，峰值不被隐藏（悬浮仍显示真实值）。
- **窗口按有数据的区间绘制**：90 天窗口在只装了 15 天的机器上不再铺 75 个空槽，并注明「90 天窗口内 15 天有记录」。
- **日桶改本地日历**：原来 `hour-hour%86400` 是 UTC 零点，在东八区分日时等于每天 08:00 到次日 08:00，今天 0 点到 8 点的流量会被算进昨天。现在前后端都按本地零点切分。
- **KPI 拆开口径**：第一格改为「Web 请求」，下方注明另含多少转发连接；「Web 错误率」的悬浮提示显示 `错误数 / Web 请求数`。原先「请求/连接」把 Web 请求与 L4 连接加在一起（37,760），而错误率分母只有 Web 请求（31,735），自己一除是对不上的。
- **「保留期内累计」只在超出所选窗口时显示**，避免 90 天窗口下同一组数字出现两次。

## 升级注意

- schema 从 7 升到 8，启动时自动迁移：删除 `site_access_events`，创建 `site_error_hours`。
- `traffic_hours` 与 `layer4_traffic_hours` 不受影响，累计请求数与流量不变。
- 错误明细从升级时刻重新累计；升级前的错误只保留在 `traffic_hours.errors` 总数里，没有再按状态码拆分的历史。
- 采集游标不变，升级不会重放或漏采日志。
