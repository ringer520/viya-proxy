# Viya v0.6.2

这一版把「配置历史」完整退役，并做了一轮全量源码清理与安全加固。**包含数据库迁移（schema 5 → 6），升级前请先备份数据目录。** 前端、接口与部署方式没有破坏性变化。

## 配置历史功能全部移除

此前每次「应用配置」都会把整份 Caddy 配置写成一条 `config_revisions` 快照（最多 50 条），供 diff 与回滚使用。它让加密配置备份膨胀到几十 MB，也把 `viya.db` 撑到 33 MB，但历史快照本身是脱敏的、不能直接回滚，实际价值有限。

- `apply.go` 不再写入快照；删除 `/api/v1/config/revisions`、`/{id}`、`/{id}/diff` 三个接口与 diff 实现；
- 「配置历史」页改名为「**备份与恢复**」，只保留配置导入导出与自动恢复点；概览页与错误提示不再引用已删页面；
- 加密导出不再包含 `config_revisions`。**旧备份仍可正常导入**：兼容层会静默丢弃里面的历史表，不会因为「未知配置表」拒绝；
- 自动恢复点保留数从 7 调整为 **5 个日期**。

在本次部署的实例上：配置导出中历史部分占明文约 31.5 MB（89.6%），移除后导出预计降到几 MB；数据库清理并执行 `VACUUM` 后从 **33 MB 降到 488 KB**。

## 数据库迁移 6

- `DROP TABLE IF EXISTS config_revisions`：老库的历史数据会被删除且不可恢复。新库不再创建这张表；
- 迁移 5 移除对 `config_revisions` 的两列 `ALTER`（避免新库升级路径依赖一张已退役的表）；
- `monitors` / `monitor_samples` 这两张早已退役的表也不再为「兼容旧备份」而创建 —— 兼容由导入层的过滤完成，全新安装不再留下空壳表。

新增 `TestRetiredTablesAreNotCreatedAndGetDropped`，同时锁定「新库不建退役表」与「老库升级后表被删除」两条行为。

## 安全加固

`validateShareRoot` 原本只拒绝 `/home` 这个父目录，`/home/<用户名>` 仍可被发布为共享 —— 而家目录里通常有 SSH 私钥与云凭证，一旦挂到公网 WebDAV 就等于交出去。现在整个用户家目录也会被拒绝，专用子目录（如 `~/share`）不受影响。已有 `TestShareRootRejectsSystemTrees` 覆盖。

## 源码清理

- 删除 `cmd/viya/config_diff.go`（仅剩一个只有单测调用的 `flattenJSON`）、`web/src/composables/useCore.ts`（零引用兼容转发层）；
- 移除 WebDAV 弹窗退役后遗留的 `copyWebDAVURL` / `webdavCopied` / `fileHosts`，以及流量 sparkline 退役后遗留的 `hourlyTraffic` / `hourlyL4Traffic` / `barHeight` / `l4BarHeight` 及其辅助计算；
- 清理 `revision-*` / `diff-*` / `op-revision-summary` 等约 20 个失效 CSS 选择器，把误导性的 `.revision-empty`（其实是通用空态样式）改名为 `.empty-state`；
- `en.json` 清掉 419 条既不在前端也不在后端出现的孤立翻译键（2168 → 1750）；
- 删除 3 张未引用或内容与标题不符的文档截图，README 双语同步修正截图表与数据表说明。

合计 54 个文件变更，`+184 / −1316` 行。

## 升级注意

- **有 schema 变更**：请先备份 `/var/lib/viya`（尤其是 `viya.db` 和 `master.key`），再替换二进制。迁移在服务启动时自动执行，无需手工操作。
- 历史数据在新版中不再可见。若需要留档，请在升级前导出一份旧备份；旧备份文件本身不会自动变小，若要小体积备份请在新版里重新导出一次。
- SQLite 删除表不会自动收缩文件。想让 `viya.db` 真正变小，需在停机时执行 `VACUUM`（本次部署已执行）。
- `/api/v1/config/revisions*` 若有外部脚本调用需要移除；`PUT /api/v1/webdav-settings` 的 410 退役行为保持不变。
- 无新依赖，systemd unit 与安装脚本未改动。
