# Viya v0.6.6

这一版修掉「流量统计在重启 / 升级后归零」的完整链路。先说诊断结论：**历史数据从来没有丢**。实测一台自更新多次的机器上，`traffic_hours` 保留 15 天、245 个小时桶、67,194 请求；schema 迁移 1–7 没有任何一处 DROP / DELETE 流量表，自更新只替换二进制。用户看到的「归零」是显示口径与几个采集缺陷叠加造成的，其中两处会真实影响后续统计。

## 一、为什么看起来归零

后端 `GET /api/v1/proxy-hosts/traffic` 一直同时返回 `total`（全表累计，重启不丢）和 `recent`（所选窗口内的量）。但前端 `useTraffic.ts` 的概览总数、站点列表总数、排行榜、趋势、错误率**全部只读 `recent`**，`total` 从未渲染。默认窗口是 24 小时且相对当前时间滑动，隔天打开数字自然变小，窗口内没有流量就是 0。

现在概览「流量分析」卡片在窗口 KPI 下方增加一条 **「保留期内累计」**，显示持久化的 `total`（请求 / 连接、上行、下行），并标注「重启 / 升级不清零」。它与所选周期无关；超过保留期（默认 90 天，可配 30–365 天）的历史会被清理，所以这是「保留期内累计」而不是永久总量，悬浮提示里也写明了。

## 二、采集停摆（真实故障）

Caddy 的 `viya_access` 与 `layer4` 两条自定义日志都没有设 `include`，而 Caddy 默认把**每一条**日志写进每一个自定义 log。实测两个日志文件里有 **306 条完全相同**的访问事件，且首行都是同一条 `tls.cache.maintenance` 启动日志。

采集端用 `sha256(首行)` 作为日志的 generation，按 generation 存 `offset / complete`。当某个轮转文件读完被标记 `complete=1`，与它同首行的 **active `access.log` 就会在 `traffic.go` 每 2 秒直接 `return`** —— 之后 HTTP 访问日志再也不入库。线上实测该文件的采集记录停在 11-08，统计全靠 `l4-access.log` 里的重复副本兜着；这个「意外兜底」一旦遇到配置变化就会彻底停摆。

修复：

- **日志分流**：`viya_access` 加 `include: ["http.log.access"]`、`layer4` 加 `include: ["layer4"]`（Caddy 按 logger 名前缀匹配）。HTTP 访问日志只写 `access.log`，L4 连接日志只写 `l4-access.log`，不再重复写入、首行也不再相同。日志配置抽成 `loggingConfig()` 纯函数并加单测。
- **游标按文件独立**：`complete` 短路改读 `traffic_files` 的 path 级状态；`offset` 以 path 为准，`traffic_cursors` 只在「文件首次以新名字出现（轮转）」或「同一路径首行变化（重建）」时用于内容续接。
- **内容指纹带日志家族**：`trafficGeneration()` 把 `http` / `l4` 前缀一起哈希，跨文件同首行不再共用 generation。
- **越界自愈**：普通日志文件 `offset > 文件大小` 时把游标收敛到当前末尾并写 WARN，不重放已入库的历史，避免升级后统计翻倍。gzip 文件跳过该判断 —— 它的 `stat.Size()` 是压缩后大小，与解压流偏移不可比。
- **启动预写内容游标**：`seedTrafficCursors()` 在启动时为两个 active 日志登记当前末尾偏移，即使 Caddy 因配置变更轮转日志，轮转副本也会继承该偏移而不会被从头重采。

## 三、配置恢复会真的清空统计

恢复 / 回滚配置时 `DELETE FROM proxy_hosts` / `layer4_rules` 会触发 `ON DELETE CASCADE` 清空流量表，而 `layer4_traffic_hours` 既不在 `runtimeTables`、也不在 `restoreRecoveryRuntime` 的引用映射里，恢复后永久归零。现在把它纳入捕获表与引用过滤（`rule_id → layer4_rules`），与 Web 流量一样按仍存在的对象写回。

## 四、升级注意

- **无 schema 版本变更**（仍为 7）。`traffic_files` 会在启动时自动补一列 `generation`，旧库平滑升级，无需手工迁移，无需改 systemd unit 或站点配置。
- 升级会重载 Caddy 日志配置。预写游标 + 越界自愈保证**已入库历史不会被重采、统计不会翻倍**；代价是重载瞬间可能漏采极少数正在写入的日志行。
- 概览累计值在升级后立即可见，无需刷新数据库或等待新数据。
- 建议升级前照旧备份 `/var/lib/viya`（`viya.db` 与 `master.key`）。
