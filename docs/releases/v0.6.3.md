# Viya v0.6.3

这一版收口「从不同 IP 打开看到两套面板」的完整链条：让一个面板实例同时拥有局域网与本机回环监听，并补上防止第二个实例被误启动、误共存的机制。**没有数据库迁移，没有接口破坏性变化，不需要修改 systemd unit 或站点配置。**

## 问题回顾

生产环境曾出现两个独立的 Viya 进程：systemd 主服务绑 `192.168.1.16:8181`、使用 `/var/lib/viya`；另一个孤儿进程（执行 `viya version` 时误启动）使用默认 `127.0.0.1:8181` 与 `/root/data`。两个地址在内核层面不冲突，各自有一套数据库与账号；而 `viya.santi.fun` 站点的上游又写死 `http://127.0.0.1:8181`，于是走域名看到的是孤儿实例、走局域网 IP 看到的是主服务。

根因不是「产品强制监听 loopback」，而是缺少三样东西：命令行参数边界、单实例保护、以及「具体 IP 绑定时回环不可达」的产品处理。

## 双监听：绑定具体 IP 时自动补回环

当 `VIYA_LISTEN` 是一个具体的非回环 IP（如安装脚本写入的局域网地址）时，**同一个进程**除主地址外还会监听 `127.0.0.1:<端口>`，并在 IPv6 可用时补 `[::1]`。所有 listener 共用一个 `http.Server`、一套会话和一份数据库：

- 本机健康检查、自反代站点即使写 `127.0.0.1:<端口>` 也会落到同一个面板，不会再连到别的进程或返回 502；
- 不需要把绑定改成 `0.0.0.0`，Docker 网桥、VPN 与其它网卡依然连不上面板，暴露面不变；
- `0.0.0.0` / `::` / 回环地址本身已覆盖本机，不会重复创建监听；主机名不做猜测，不额外绑定；
- `::1` 不可用（IPv6 被禁用）时静默跳过，`127.0.0.1` 被占用时告警但不影响主监听启动。

启动日志新增 `addresses` 字段列出全部实际绑定地址。`ss -lntp | grep 8181` 现在可能有多行，只要属于同一个 PID 就是正常的。

## 命令行参数边界

此前二进制忽略所有参数：执行 `viya version` 会启动一个完整面板，这正是孤儿进程的来源。现在：

- `viya version` / `--version` / `-v` 打印构建信息（版本、commit、构建时间、来源、schema 版本、runtime）后退出 0；
- `viya help` / `--help` / `-h` 打印用法后退出 0；
- 任何其它参数报错并退出 2，**绝不静默启动服务**；
- 无参数行为不变。

## 单实例锁

在 `VIYA_DATA_DIR` 下创建 `viya.lock` 并独占：Linux 用 `flock`，Windows 用 `LockFileEx`。进程退出（含被强杀）后由操作系统自动释放，不会留下需要手工清理的 stale 锁。使用同一数据目录的重复启动会被拒绝，并在日志里打印具体目录。备份脚本 `scripts/backup_archive.py` 已排除该锁文件，不会把它打进归档。

## 启动自检与可观测性

- `warnOnSharedPanelPort`：在任何 listener 绑定前用通配端口探测，若同端口已被其它地址占用则告警，并提示「比较启动日志的 data_dir / pid 后停掉多余进程」；
- `warnLoopbackSelfProxies`：检测「面板绑局域网 IP、站点上游却指向 loopback」的错位，给出具体修正地址。**只告警，不自动修改用户配置。** v0.6.3 起若本进程已监听回环，则不再告警，因为该上游此时是可达的；
- `Viya API listening` 日志补齐 `addresses` / `data_dir` / `version` / `commit` / `pid`；
- 清理 4 处仍指向已删除「配置历史」的英文日志文案。

## 监听默认值统一

Go 侧把散落在 `main.go`、`web_listeners.go`、CLI 帮助里的 `127.0.0.1:8181` 字面量收敛为单一常量 `defaultPanelListen`，避免端口判定与实际监听漂移。安装脚本的 `0.0.0.0:8181` 默认值**有意保留**：服务器安装需要局域网可达，改成自动探测网卡 IP 会在多网卡、容器与 IPv6 环境引入回归；脚本内已加注释说明两者差异，以及可用 `VIYA_INSTALL_LISTEN=<LAN_IP>:8181` 收窄绑定。README 双语补充了三种绑定方式与 `ss` 的正确读法。

## 升级注意

- 直接替换二进制并重启即可，无 schema 变更、无配置迁移、无需改站点上游。
- 若之前把 `VIYA_LISTEN` 改成了 `0.0.0.0` 只为让本机 `127.0.0.1` 可用，现在可以改回具体的局域网 IP，暴露面更小且本机仍可访问。
- 若机器上仍有旧的孤儿实例，它会在新版启动时因回环端口被主服务占用而直接失败；建议按启动日志确认后停掉并备份其数据目录。
- Docker 环境变量、`install.sh`、systemd unit 均无变化。
