# Viya v0.6.5

这一版修掉三个会影响真实使用的缺陷，并把文档版本与仓库社区文件补齐。**无数据库迁移、无接口破坏性变化、无需修改 systemd unit 或站点配置**，直接替换二进制并重启即可。

## P0：文件与共享不再生成错误的访问地址

`GET /api/v1/file-shares` 的 `url` 由后端 `shareURL()` 根据站点绑定的监听器生成，会带上正确的协议与非默认端口；监听器配置缺失时该字段**有意为空**。但前端 `web/src/components/file-shares/types.ts` 的 `shareAddress()` 在 `url` 为空时会拼出一个 `https://<域名><路径>` 的兜底地址，忽略 `tls_mode`、协议与端口，而 `mountCommands()` 又基于它生成 Windows / macOS / Linux / rclone 四条挂载命令——结果是四条都能复制、但一条都连不上。

修复：

- `shareAddress()` 只返回后端地址（做 trim），**不再伪造**；
- `url` 为空时 `mountCommands()` 返回空数组，「挂载命令」按钮与命令列表都不再出现；
- 地址显示、复制、打开链接与挂载按钮统一以 `shareAddress()` 判断，避免两处标准不一致；
- 界面保留原有提示「监听信息不可用，暂时无法生成访问地址。」，引导先修监听器配置。

新增单测覆盖：非默认端口、明文 HTTP 地址、空 URL 与纯空白 URL、以及「空 URL 时不得出现裸域名兜底」。

## P0：监听默认值的文档矛盾已消除

此前 `README.md` / `README.en.md` 第 28 行写「默认监听 `0.0.0.0:8181`」，同一份文档后面的「只运行一个面板实例」又说未配置的二进制默认 `127.0.0.1:8181`。两者其实分别对应不同部署方式，但表述含混，VPS 用户容易误判暴露面。

现在明确区分：

| 部署方式 | 默认 `VIYA_LISTEN` |
| --- | --- |
| 直接运行未配置的二进制 | `127.0.0.1:8181`（仅本机） |
| `install.sh` / systemd 安装 | `0.0.0.0:8181`（所有网卡） |
| Docker 镜像 | `0.0.0.0:8181`（所有网卡） |
| 安装时指定 `VIYA_INSTALL_LISTEN=<局域网IP>:8181` | 具体局域网 IP（v0.6.3 起同一进程自动补回环） |

`install.sh` 完成提示也改为读取 systemd 单元里**实际写入**的 `VIYA_LISTEN` 再输出：回环绑定提示走 SSH 隧道、通配绑定提示限制防火墙、具体 IP 提示确认可达性，不再一律声称「监听所有网卡」。

## P0：自更新不再吞掉 Caddy 引擎替换失败

v0.6.4 之前 `version.go` 对 Caddy 二进制替换使用 `_ = replaceExecutable(...)`。Caddy 是子进程，替换失败不致命（主程序仍可重启），但静默吞错会导致界面显示「更新成功」，而实际运行的是**新版主程序 + 旧版引擎**。

现在 `swapEngineBinary()` 在失败时：

- 写一条结构化 `WARN` 日志（含路径与原始错误，仅进程序日志，不回传客户端）；
- 把固定的、不含内部路径的提示写入更新进度 `warning` 字段，供 `GET /api/v1/version/update/status` 轮询读取；
- 在 `POST /api/v1/version/update` 的两个成功响应（自动重启 / 等待手动重启）里一并带上 `warning`；
- 前端版本面板显示琥珀色告警条，并通过 `sessionStorage` 在重启刷新页面后依然可见，可手动关闭；新一轮更新开始时自动清空。

**行为不变**：引擎替换失败仍然不阻断更新与重启，只是从「假成功」变成「成功但明确告警」，符合「只告警、不自动改用户配置」的原则。新增单测覆盖替换成功/失败两条路径，以及告警在后续进度阶段不被覆盖。

## 文档一致性与发布门禁

- `docs/项目说明.md` 从「当前发布 v0.5.3」更新到 v0.6.5，并修正三处过时事实：Go 文件数（约 70 个非测试文件 + 38 个测试）、`applyLocked()` 实际位于 `config_apply.go`、旧 `logRequests` 已被 `requestIDMiddleware` 取代。
- `scripts/check_release_version.py` 现在除两份 README 的安装片段外，还强制校验项目说明里的「当前发布」与「最新版本说明」都指向待发布 tag，并确认 `docs/releases/<tag>.md` 存在。此前文档版本每次发布都靠手工改、脚本漏检，v0.5.3 的问题曾反复出现。

- 旧备份可正常导入，配置导出与恢复点表清单未变化。
