# Viya v0.6.1

这一版补完 v0.6.0 遗留的两件事：让共享成为一等站点，以及把流量历史真正放出来。数据库结构不变，可直接升级。

## 变更：共享统一走站点表单，旧的 WebDAV 弹窗退役

v0.6.0 的「文件与共享」页里，「WebDAV 设置」按钮打开的还是旧弹窗。它把共享写死成纯 HTTP（`tls_mode=none`、无监听、无目录浏览），而且用 `WHERE type='files' LIMIT 1` 查库，全局只能存在一个共享，再次保存会覆盖上一条——公网 HTTPS 访问因此只能绕道建站点。

本次：

- 工作台右上角改为「新建共享」，直接打开站点表单（预填 `type=files`），共享因此天然支持 HTTPS 监听、DNS-01 通配符证书、多实例与 IP 白名单、限速等常规访问控制；
- 删除 `WebDAVSettingsModal.vue` 与 `webdav-modal.css`；
- `PUT /api/v1/webdav-settings` 退役，返回 `410 Gone` 并带 `Deprecation` / `Sunset` 响应头；`GET` 保留一个版本只读兼容，响应新增 `deprecated: true`；
- 旧弹窗创建的数据不受影响：它们本来就是普通 `files` 站点，会照常出现在清单里，只是会被标记为「明文 HTTP」并引导迁移。

## 安全默认值

- 新建 `files` 站点默认开启目录浏览与 WebDAV、默认要求访问认证、默认只读；
- `validateHost` 拒绝「未认证 + 允许 WebDAV 写入」：匿名可写等于让任何猜到地址的人上传和删除文件。**公开只读下载仍然允许**，这是正常用法；
- `validateShareRoot` 拒绝把 `/`、`/etc`、`/home`、`/root`、`/usr`、`/proc`、`/sys`、`/var/lib/viya` 等系统树发布为共享；
- 工作台卡片新增 TLS 状态（`HTTPS` / `明文 HTTP`）与常驻警示，暴露面一眼可见。

## 新增：流量区间到 90 天

`traffic_hours` 一直保留 90 天小时数据，但接口只认 `24h` / `7d` / `30d`，更早的历史在库里却看不见。

- `GET /api/v1/proxy-hosts/traffic` 与 `/api/v1/layer4-rules/traffic` 支持 `range=90d`，并额外接受 `range=days=N`（1–90，越界回退 24h）；
- 概览「流量分析」新增「90 天」按钮，`TrafficTrend` 按天聚合渲染。

## 引导：已有 NAS 可以直接反代它的 WebDAV

文件与共享页新增引导卡。群晖、威联通、TrueNAS 都能开启 WebDAV，用现有「Web 服务 → 反向代理」指向它即可复用面板的 HTTPS 证书、访问认证与限速，**不需要额外进程或系统权限**。这比把 SMB 挂进面板更轻，也不动 `viya.service` 的权限边界。

## 升级注意

- `PUT /api/v1/webdav-settings` 已移除。仍在使用旧前端的部署需要刷新页面；脚本调用需改为 `POST /api/v1/proxy-hosts`。
- 已有的匿名可写共享会在下次编辑保存时被拒绝，需要先开启访问认证或关闭写入。
- 无数据库迁移、无新依赖、systemd unit 未改动。

## 验证

`go vet ./...`、`go test ./...`、`pnpm --dir web build`、`typecheck`、`lint`、`vitest`（20 用例）、`scripts/check_i18n.py` 全绿；临时实例 HTTP 冒烟确认 `PUT /api/v1/webdav-settings` 返回 410、匿名可写创建返回 400、`range=90d` 与 `range=days=7` 返回 200。
