# Viya v0.6.4

这一版修掉一个会让面板「自己把自己关掉」的缺陷，并补上配置变更审计与请求追踪。**新增数据库迁移（schema 6 → 7，只加一张轻量表）**，无接口破坏性变化，无需修改 systemd unit 或站点配置。

## P0：重启只在确实有人会拉起进程时发生

此前有三个地方会主动结束进程并依赖服务管理器重启：修改面板监听端口（`panel_settings.go`）、自更新（`version.go`）、端口变更超时回滚（`panel_recovery.go`）。其中**改端口完全没有环境检测**：在容器、OpenWrt 裸进程或任何手工启动的场景下，进程一退出就再也不会起来，面板从网页上把自己锁在门外。自更新也只排除了容器/非 Linux，未校验是否真的有 supervisor。

v0.6.4 统一为一个入口 `requestProcessRestart`：

- `detectRestartSupervisor` 读取 `/proc/self/cgroup` 与 `/proc/1/comm`。只有 **systemd 系统单元作用域**（含 `.service` 且不在 `user.slice`）或 **OpenWrt procd** 才判定为受管；SSH 会话里手工运行的进程虽然有 systemd 作为 PID 1，但落在 `user.slice/session-*.scope`，会被正确识别为「无人拉起」。容器一律按不受管处理。
- 检测不到服务管理器时**不结束进程**：改监听端口返回 409 与明确原因（不保存端口）；自更新仍然安装新二进制，但返回 `restart_required: true` 并在界面提示手动重启；端口回滚只记录告警。
- 计划内重启统一以退出码 **75** 结束（先完成 `http.Server.Shutdown` 排空请求）。`Restart=always` 忽略退出码，`Restart=on-failure` 也会拉起；此前干净退出 0 在 `on-failure` 下不会重启。
- 启动日志会打印 `planned restart requested` 及原因，便于在 journal 里区分「计划重启」和真实故障。

行为变化需要留意：容器或手工运行的实例现在**不能通过面板改监听端口**（请改环境变量 / compose 映射后手动重启），自更新后也不会自动消失。检测保守，宁可提示手动操作也不冒离线风险；若使用 `systemd --user` 单元，同样会走手动路径。

## P1：配置变更审计

上一版删除了 `config_revisions`（它把备份撑到几十 MB），但也就失去了「谁在什么时候改了什么」的线索。这版用一个**只存摘要**的表补回来：

- `config_audit` 每条只存账号、HTTP 方法、路径、动作摘要、状态码、`request_id`、时间；**不存整份配置**，保留 2000 条 / 90 天。
- 复用 `requireSession` 已有的 `operationContext{Summary, Actor}`，在请求结束后按真实状态码记录，**只记成功的写操作**；登录相关事件仍由 `login_audit` 负责，不重复。
- `GET /api/v1/config-audit` 支持时间范围与关键词筛选；日志页新增「**配置变更**」标签页。
- 该表**不进加密配置导出，也不进恢复点归档**（既不在 `configTables` 也不在 `runtimeTables`），审计数据只属于本机。

## P1：请求 ID 贯穿

`requestIDMiddleware` 取代原来的访问日志中间件：为每个请求生成 16 位 hex ID，写入 `X-Request-Id` 响应头、`context`、访问日志与失败日志；审计行也带上同一个 ID，一次误操作可以从浏览器响应一路关联到服务端日志。`requestLogAttrs(r)` 供业务日志继续透传。

## 升级注意

- 迁移 7 在服务启动时自动创建 `config_audit` 表，不需要手工操作；**升级前仍建议备份** `/var/lib/viya`（`viya.db` 与 `master.key`）。
- 用面板自更新时，新二进制由服务管理器拉起；Debian 自带 unit 为 `Restart=always`，可正常完成。
- 容器部署请继续用「拉取新镜像并重建」的方式，面板里的自更新入口仍会按 Docker 环境禁用。
- 旧备份可正常导入：`config_audit` 不出现在归档里，不会触发「备份包含未知配置表」。
