# 源码排查记录

本轮重点检查 Web 监听、Caddy 配置生成、上游地址、DDNS、异步页面刷新和删除流程。按要求仅修改源码，不编译、不发布。

已修复：

- 关闭自动调度的 DDNS 任务无法手动更新；现在定时任务与手动执行分开判断。
- DDNS 网络请求超时后无法记录执行结果；执行记录使用独立的短时数据库写入上下文。
- DDNS 执行期间允许编辑或删除，导致旧执行结果写入新任务配置；相关操作统一加锁，后台批量任务逐条释放锁并再次检查调度时间。
- 一秒轮询发生请求重叠时，新请求不断让旧响应失效；现在合并正在进行的轮询，操作完成后强制获取新状态。
- 刷新覆盖删除错误、请求异常无人处理；删除统一处理请求异常并在刷新后保留错误提示。
- 多次全页刷新可能由旧响应覆盖新状态；以请求序号保护整批状态更新。
- DNS 服务商 Zone 请求乱序覆盖；忽略过期响应。
- 编辑指定 IPv6 时，表单监听器无条件改用默认地址；仅在当前地址不可用时重新选择。
- HTTPS 端口检测遗漏 HTTP/3 UDP 占用；检查 TCP 和 UDP，并与四层转发互相检测冲突。
- 监听设置暂存与回退过程中可能被其他配置应用读取；设置写入、Caddy 应用及失败恢复共用配置锁；监听、四层转发、面板端口修改共享端口配置锁。
- 数据库中损坏的监听配置缺少结构校验；读取和保存均验证协议、端口、重复项及基本监听数量。
- 上游地址末尾空端口、无方括号 IPv6 缺少明确错误提示；补充校验。

检查方式：Go 源码语法格式检查、Vue/TypeScript 源码语法解析、接口调用与 SQL 字段的源码复核。尚未进行类型检查、编译、运行测试和浏览器验证；这些留待允许构建后完成。
