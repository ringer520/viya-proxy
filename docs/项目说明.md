# Viya 项目书

> 面向接手此项目的新开发者 / AI 助手的一页式全貌说明。目标是**读完本文档即可动手改代码、加功能、定位问题**，无需翻完整历史。

- **项目名**：Viya —— 一个自托管的 Caddy 反向代理管理面板
- **一句话定位**：单二进制、零运行时依赖，用 Web 控制台管理反向代理 / 静态站点 / URL 重定向 / 四层端口转发。
- **仓库**：<https://github.com/ringer520/viya-proxy> · 协议 MIT · 发布版本 v0.3.0

## 1. 架构总览（三层协同）

```
┌─────────────────────────────────────────────────────────────┐
│                        浏览器 (Vue 3)                        │
│   打包后经 go:embed 内嵌进二进制，同源访问 /api/v1/*         │
└──────────────────────────────┬──────────────────────────────┘
                               │ HTTP (JSON, session + CSRF)
┌──────────────────────────────▼──────────────────────────────┐
│              控制平面 Control Plane（Go + SQLite）            │
│  站点/证书/DNS/封禁/流量/安全策略 全部业务逻辑                 │
│  启动 Caddy、生成 Caddy JSON、校验、热加载、崩溃自动拉起        │
└──────────────────────────────┬──────────────────────────────┘
                               │ Caddy Admin API (127.0.0.1:2019)
┌──────────────────────────────▼──────────────────────────────┐
│              代理引擎 Engine（Caddy，自定义构建）              │
│  真正承载流量：reverse_proxy / file_server / 重定向 / L4       │
└─────────────────────────────────────────────────────────────┘
```

- **交付物是单个静态二进制**：前端内嵌、数据库是单个 SQLite 文件、Caddy 一起打包，**无需 Node、无需外部数据库**。
- **Viya 和 Caddy 是两个独立 Go module**，可以分别构建：改业务逻辑/前端只重编 Viya；改 DNS 插件才需要重编 Caddy。

## 4. 核心领域概念

### 4.1 站点类型（`proxy_hosts.type`）

| 值 | 含义 | Caddy 编译目标 |
| --- | --- | --- |
| `proxy` | 反向代理 | `reverse_proxy`（HTTPS 上游自动配 transport） |
| `static` | 静态站点 | `file_server`（root 指向磁盘目录） |
| `redirect` | URL 重定向 | `static_response` + Location 头（301/302/307/308，可保留路径） |

前端类型选择器用三种主题色区分：反向代理蓝 `#3b82f6`、静态站点青绿 `#14b8a6`、重定向橙 `#f97316`（`useHosts.ts` 的 `siteTypeOptions`）。

### 4.2 监听器（`WebListener`）

- 每个监听器 = `{id, protocol: http|https, port}`，独立管理自己的站点集合。
- 默认两个：`https-main:443`、`http-main:80`，可在面板增删（数量 2–20）。
- 站点通过 `listener_id` 归属到监听器；纯 HTTP 站点只能挂 HTTP 监听器。
- 端口检测（`listenerPortAvailable`）：先试 `net.Listen`，失败再问 Caddy admin 是否它自己占的。

### 4.3 安全策略三层继承（重点功能）

浏览器防护、IP 白黑名单、限速、请求体上限、HTTP 方法及隐藏 Server 按**三级策略**解析。Basic Auth 和上游请求头由站点独立管理，不随默认策略修改。

1. **全局默认**（`panel_settings` 的 `security_global_defaults`）
2. **域名策略**（`security_domains_defaults`，如 `example.com`，也支持更具体的子域）
3. **站点自身策略**（`proxy_hosts.security_headers` 等列）

站点模式为 `follow / custom / none`：跟随域名、独立配置或不使用默认策略。域名模式为 `inherit / custom / none`；`none` 会停止向上回退，全局策略不能选择继承。响应头的 `enabled` 只控制响应头，不影响 IP 或请求限制。

跟随站点在生成 Caddy 配置及读取站点列表时动态解析，按域名后缀逐级匹配，**最具体的域名优先**，最终回退全局；不会批量覆盖独立站点或更具体的域名策略。旧 `inherit` 标记仍兼容读取。前端 `useSecurity.ts` 的 `resolveSecurityPolicy()` 与后端 `security_policy.go` 的 `resolvePolicySource()` 需保持一致。

保存前通过 `POST /api/v1/security-defaults/preview` 计算同步、独立和其他域名策略的站点数量。保存后同步应用引擎；失败时恢复原设置和内存中备份的实际引擎配置。全局入口位于面板设置的“面板访问”，域名入口位于 Web 服务的域名组。

### 面板设置交互

- `PanelSettingsDrawer.vue` 管理外观、刷新、访问与安全、账户和通知，记住上次分类；外观和刷新偏好在当前浏览器即时生效，服务器配置单独提交。
- 端口、账户及通知草稿跨分类保留；关闭按钮、Esc、快捷键及离开页面均检查未保存内容。放弃后清空草稿并恢复页面滚动，只读账户仅能修改浏览器偏好及自身密码。
- `SettingsVersionPanel.vue` 独立处理版本检查、更新进度与重启等待；有草稿时禁止更新，确认目标版本与引擎恢复后自动刷新，并在卸载时清理轮询。
- 通知测试仅使用已保存配置；账户编辑表单默认折叠，权限管理和其他账号操作仅对管理员开放。

### 4.4 其他

- **上游**：`http(s)://host:port`，端口可省略（默认 80/443）。
- **证书来源**（`tls_mode`）：`auto` / `http-01` / `dns-01` / `internal` / `custom` / `none`。
- **流量统计**：Web 站点与 L4 转发共用 `traffic_hours`，24h/7d/30d 窗口。

## 5. 数据模型（核心表）

SQLite，单连接（`SetMaxOpenConns(1)`）+ WAL。表结构在 `main.go` 的 `main()` 与各 `*_schema.go` 中定义，迁移用 `ensureColumn()` 增量补列。

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `proxy_hosts` | Web 站点 | `domain, listener_id, type, upstream, root_path, spa_fallback, browse, redirect_target, redirect_status, redirect_keep_path, tls_mode, icon_color, security_headers(JSON), custom_headers(JSON), ip_allowlist/denylist(JSON), rate_limit_*, max_body_bytes, allowed_methods(JSON), hide_server, version(乐观锁)` |
| `web_listeners`（存 `panel_settings`） | 监听器列表 | JSON 数组 |
| `layer4_rules` | 四层转发 | `listen_address, listen_port, protocol, upstream, version` |
| `dns_providers` | DNS 凭据 | `provider_type, credentials_ciphertext, credentials_nonce, key_version` |
| `ddns_records` / `ddns_runs` | DDNS 任务与运行历史 | `record_type, interval_minutes, ip_source, interface_name` |
| `custom_certificates` / `managed_certificates` | 证书 | `cert_path, key_path` / 申请进度 |
| `ip_bans` | 封禁 | `domain, ip, expires_at, source(manual/auto)` |
| `config_revisions` | 配置快照 | `status, config_json(脱敏), error_text` |
| `users` / `sessions` | 账号 / 会话 | `password_hash` / `token_hash, csrf_token, expires_at` |
| `panel_settings` | 键值设置 | `listen_port, web_listeners, security_global_defaults, security_domains_defaults, alert_settings` 等 |
| `login_attempts` / `login_audit` | 登录限速 / 审计 | |

> **站点「保存后未应用」的状态**用 `version` 乐观锁 + 前端 `partialSave` 标志处理，`POST /config/apply` 重新应用。

## 6. 后端设计要点

### 6.1 HTTP 路由与中间件链

```go
server := &http.Server{Handler: securityHeaders(logRequests(recoverPanic(mux))), ...}
```

- **`recoverPanic`**：最内层，捕获任何 handler panic，记录完整堆栈并返回 500 JSON，**避免连接被重置导致前端看到裸的 "Failed to fetch"**（见 8.3 的踩坑）。
- **`logRequests`**：Debug 级请求日志。
- **`securityHeaders`**：给面板自身响应加安全头。
- 所有业务路由为 `GET/POST/PUT/DELETE /api/v1/...`（Go 1.22+ 的 method+path 路由），除 auth 外都经 `requireAuth`（session + 写操作再校验 CSRF）。前端静态资源走 `GET /` 的 `web.Handler()`（SPA fallback）。

### 6.2 Caddy 配置生成与 apply 流程

核心在 `main.go` 的 `applyLocked(ctx)`：

1. 读所有 `enabled=1` 的站点 → 构建 `routes`（每个站点一组 `match{host,path}` + `handle[]`）。
2. 中间件 handler 顺序（每站点）：`authentication` → `rate_limit` → `headers(request)` → `headers(response)` → `request_body` → **`encode`(gzip+zstd)** → 最终 `file_server` / `reverse_proxy` / `static_response`。
3. 组装 `http.servers`、`tls.automation.policies`、`layer4`、`logging`。
4. 写临时 JSON → `caddy validate --config` 校验 → `POST {adminURL}/load` 热加载 → `recordRevision` 存快照。
5. 失败则回滚（恢复旧快照/旧监听器设置），返回 502；前端收到 502 显示「重新应用」按钮。

**apply 触发**：写操作直接调 `apply()`；自动封禁等高频变更走 `scheduleApply()`（500ms 去抖，`applyWorker` 串行消费 `applyKick` channel）。

### 6.3 锁与并发

- `a.mu`：保护「生成配置 + 校验 + 加载」整个 apply 临界区（`apply()` 先拿 mu 再调 `applyLocked`）。
- `a.listenerMu`：保护监听器变更。**锁顺序统一为 `listenerMu → mu`**（`saveWebListeners`、`config_archive` 等），无反向获取，避免死锁。
- SQLite 单连接：写操作天然串行，`busy_timeout=5000`。

### 6.4 安全细节

- DNS 凭据 AES-256-GCM 加密（`internal/secretstore`），主密钥在 `master.key`（备份外）。
- 首次管理员账户可从任何可访问面板的 IP 创建；初始化前应避免将面板暴露到不可信网络。
- 配置快照脱敏（`redactConfig`），密码/basic auth 等敏感值不落盘明文。

## 7. 前端设计要点

### 7.1 状态管理模式：模块级单例 composables

**没有 Pinia/Vuex**。所有共享状态用**模块级 `ref` 单例** + 具名导出，组件直接 `import { hosts } from "../composables/useCore"` 引用同一个响应式实例。

- 优势：零模板代码、类型安全、按领域切分清晰。
- 约定：跨模块引用通过**函数体 / computed getter 内延迟访问**（避免模块求值期 TDZ，见 7.3）。

### 7.2 组件分层

- **App.vue（壳）**：认证屏、导航、面板设置抽屉、定时器、`watch`、生命周期；页面用 `v-if="activeSection==='x'"` 挂在壳里，页面组件内部不再含该守卫。
- **页面组件**（`*Page.vue`）：直接 import composables 拿数据，不接 props。
- **弹窗组件**（`*Modal.vue`）：同理由 composables 驱动显隐（`show` 等 ref）。
- **`v-dialog` 全局指令**：焦点陷阱 + Esc/点击遮罩关闭。

### 7.3 循环依赖与 `useApply` 拆分（重要踩坑）

ESM 模块间存在**循环 import**（如 `useCore ↔ useHosts`）。生产 `vite build` 靠 Rollup 重排能通过，但 **dev 原生 ESM 会因 TDZ 白屏**。两条铁律：

1. **模块级禁止在求值期读取 import 的绑定**——`watch()` 即使非 immediate 也会先跑一次 getter，所以在模块顶层 `watch(selectedInterfaceAddresses,...)` 直接读了还没初始化的 `useCore` 状态 → `Cannot access 'x' before initialization`。
2. **把会形成 `useCore→useNetwork→useCore` 闭环的 `retryApply` 拆到独立的 `useApply.ts`**，斩断该环。其余循环因无模块级 watch 且都在函数体/computed 内惰性访问而安全。

### 7.4 主题系统

- 5 套 palette：`light / dark / aurora / ember / cyber`，`<html data-palette>` + `theme.css` 的语义 token（`--surface/--line/--text/--accent` 等）。
- 站点类型/状态色用 `color-mix(in srgb, var(--tcolor) N%, transparent)` 跟随主题。
- 遵循 A 股约定：涨红跌绿（本面板暂不涉及行情，但流量/健康态配色保持语义一致）。

## 8. API 约定

- **认证**：登录 `POST /api/v1/auth/login` → 服务端 session（`Set-Cookie`，`SameSite` + Secure）。写请求带 `X-CSRF-Token`（来自 `GET /auth/me`）。
- **响应格式**：成功返回 JSON 体（或 204）；错误统一 `{"error": "..."}`（中文文案，`t()` 前端翻译）。
- **部分保存**：某些写操作在 Caddy 未就绪时会「先落库，返回 502 + 标记未应用」，前端 `applyRetryVisible` 显示「重新应用到 Caddy」按钮调 `POST /config/apply`。
- **错误提示**：前端所有 `t(e.message)` 会把 `Failed to fetch` 等网络错误映射为「网络请求失败，请检查服务是否运行」（`i18n.ts` 的 `friendlyErrors`）。

## 9. 构建 / 运行 / 部署

### 9.1 构建

```sh
# 前端（产出到 internal/web/dist，go:embed 依赖它）
cd web && npm install && npm run build

# Viya 二进制（会内嵌前端）
cd .. && go build -o viya.exe ./cmd/viya

# Caddy 二进制（独立 module，含插件）
cd build/caddy && go build -o ../../bin/caddy .
```

### 9.2 本地预览（开发）

```sh
VIYA_DATA_DIR=./data VIYA_LISTEN=127.0.0.1:8181 \
VIYA_CADDY_BIN=./bin/caddy viya.exe
# 浏览器打开 http://127.0.0.1:8181，首次创建管理员
```

> 注意：`dataDir` 启动时会 `filepath.Abs` 转绝对路径（静态站点留空根目录依赖绝对路径）。

### 9.3 部署

- systemd / OpenWrt procd 均支持，一键 `install.sh`，release 由 GitHub Actions 打。
- 管理端口默认回环 `127.0.0.1:8181`，建议 SSH 隧道访问；**勿暴露 Caddy admin API**。
- 关键环境变量见 README「Configuration」表（`VIYA_LISTEN / VIYA_DATA_DIR / VIYA_CADDY_BIN / VIYA_MASTER_KEY_FILE / VIYA_COOKIE_SECURE / VIYA_TRUSTED_PROXIES` 等）。

## 10. 关键设计决策与踩坑记录（新模型必读）

1. **前端 `go:embed` + SPA fallback**：`internal/web/static.go` 对不存在路径回退 `index.html`。
2. **multipart 文件名清理**：Go 1.20+ 对 filename 做 `filepath.Base`，`assets/app.js` 会丢目录 → 相对路径改走独立 `paths` 字段（`site_files.go` 上传）。
3. **循环依赖 TDZ**：`retryApply` 必须独立在 `useApply.ts`（见 7.3），否则 dev 白屏。
4. **`dataDir` 相对路径 bug**：留空静态根目录会生成相对路径被 `validateStaticRoot` 拒绝 → 启动时 `filepath.Abs(dataDir)`。
5. **无 panic recover → "Failed to fetch"**：已加 `recoverPanic` 中间件 + 前端 `friendlyErrors` 双保险。
6. **锁顺序**：`listenerMu → mu` 固定，禁止反向。
7. **CSS 特异性坑**：`.modal label{display:block}` 会压过 `.drawer-check-line{display:flex}` → 需 `.modal .drawer-check-line` 提升特异性。
8. **变量名撞车**：`siteStats` 曾与流量函数重名 → 改 `hostContentStats`。
9. **libdns/vultr 版本**：v1 与 libdns v1.1.1 不兼容 → 用 v2。

## v0.3.0 当前实现补充

- Web/四层转发列表使用独立的滚动近 30 天统计；概览仍支持 24 小时、7 天和 30 天范围。
- `GET /api/v1/proxy-hosts/error-locations` 基于保留的访问样例按站点及 HTTP 状态码分组，不推断攻击。程序错误日志不再重复计入访问统计。
- `POST /api/v1/traffic/reset` 为管理员确认操作，串行清空统计表和访问样例，保留原始日志与采集游标，并保存 `traffic_reset_at` 防止旧归档重计。业务配置导入保留当前重置边界。
- 面板设置的手动编辑标记与浏览器自动填入分开，真正未保存的修改才触发关闭确认；设置 → 存储提供清空统计入口。
- 主题素材位于 `web/public/themes`，背景使用 WebP，配套样式集中在 `anime-themes.css`；动效默认启用并遵守系统减少动态效果偏好。
- `install.sh` 为 systemd/OpenWrt 通用入口。OpenWrt 使用 `deploy/install-openwrt.sh` 和 procd/UCI，默认局域网监听 8181。
- GitHub Release 的版本正文来自 `docs/releases/<tag>.md`，通过检查后构建 Linux 三架构包和 Docker 多架构镜像。
